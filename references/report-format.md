# 金字塔研报格式

读者只有 2 分钟。信息架构的目标是：**10 秒扫完重点，想深入再往下滚**。所以正文极简、结论先行，六段全文沉底到附录。

## 为什么这样排

一份研报最容易犯的错是「把深度做成全文平铺」——5 条必读 × 每条六段 ≈ 3000 字堆在正文，金字塔顶就被压塌了。读者要的不是事件复述，而是**「这事对我意味着什么 + 我这周该做什么」**。所以：

- 正文每条必读压成 **3 行**：标题 + 一句话结论（so-what）+ 首要行动。
- 完整的六段分析（背景/影响/竞品/提效/机会/行动）移到**文末附录**，按需展开。
- 低分条目（≤5）不进正文，只在尾注给个总数 + 去哪看。

## 模板（严格遵循）

```markdown
# AI 情报{日报|周报|月报} · {period}

_☕ 正文约 N 分钟读完 · 深度解读见文末附录_

## ⚡ 今日速览

{恰好 3 句话，每句一个重点，合计 ≤120 字。直接给结论，不要「今天有以下几条」这种引语。}

## 🔥 今日必读

**1. [{中文标题≤30字}]({url})** `{importance}/10` · {N} 源 · {来源}
⚡ {so-what：这件事对 {lens} 最重要的含义，≤40 字，直击要害}
👉 {首要行动：本周可做的最具体一件事}

**2. [...]({url})** `9/10` · {N} 源 · {来源}
⚡ ...
👉 ...

（≥8 分的 Top 3-5 条；若不足，放宽到 ≥7 分取前 3。`{N} 源` 是报道面，入选门槛见下文「信源分级与报道面」）

## 📌 值得关注

- **[{标题}]({url})** `7` · {内容分类} · {来源}
- **[{标题}]({url})** `6` · {内容分类} · {来源}

（6-7 分，每条仅 1 行，最多 8 条；摘要不进正文，读者要细节自己点链接）

## 🔁 续报（可选板块）

- [{事件简称}：{本期新进展，一句话}]({url}) · {来源}

（近 7 期必读已报过、本期又达不到再进必读门槛的事件，在这里一行带过；无则省略该板块，规则见下文「事件合并与跨期去重」）

## 🔧 GitHub 开源雷达（可选板块）

> 触发：**PM / 工程师 / 研究 lens 默认带上**（PM 看产品机会与需求趋势、工程看技术选型与集成、研究看方法新意，详见 `lenses.md`）；投资 lens 当期开源有料时可选。数据来自 `github_stars` 源，它会按报告周期自动切口，避免每天重复常青仓库：**日报**看近 7 天创建的新项目；**周报**看近 30 天创建且已拿到高星的动量项目；**月报**看高星、近 180 天仍活跃的基础设施项目。GitHub API 不提供真实「近 N 天新增 star」字段，周报动量用「短期创建 + 当前高星」做代理，需在文案里保持这个边界。

按**产品 × 技术双视角**盘点 3-6 个项目（挑与当期主线呼应、产品价值清晰的；**对异常虚高 star 保持警惕、剔除明显刷量/无实质项目**，star 标注「GitHub API 实时」，若当期无足够项目就如实省略该板块）：

**① [{owner/repo}]({url})** ⭐{stars} · {语言} · `{一句话定位标签}`
- 🎯 **产品**：{解决谁的什么问题、能拿来做什么，1-2 句}
- 🔧 **技术**：{技术栈 / 架构亮点，1 句}
- 💡 **为何现在看**：{与当期主线 / 趋势的呼应，1 句}

（每个项目 3 行解读；末尾加一句「给 PM / 工程的归纳」点出共同趋势。这是 ai-radar 区别于纯新闻聚合的「产研提效」抓手）

**PM 优先跟踪类别**：AI 编码 / IDE、Agent 应用与工作流自动化、RAG / 知识库产品、MCP / 插件生态、多模态生成应用、行业场景模板。重点问：需求是否被验证、是否能集成成产品能力、会不会成为竞品或上游。

**研发优先跟踪类别**：Agent 框架与编排、推理 / runtime / serving、评测与观测、RAG 数据管线、本地模型与端侧工具、安全权限与沙箱、开发者工具链。重点问：能否落地、集成成本、性能/成本收益、是否值得 benchmark。

- **竞品对位**：{2-3 句}
- **{lens}视角启示**：{结合视角的可落地动作}
- **机会信号**：{商业/技术/投资机会，随 lens 而定}

  - {动作1}
```

## 信源分级与报道面

`fetch.py` 给每条材料带上 `tier`（取自 `sources.json`）；WebSearch / WebFetch 补抓的材料按域名自行判定。

| 级别 | 含义 | 例子 | 代表稿 | 计入报道面 |
|---|---|---|---|---|
| T1 | 官方一手 | 厂商官网、官方博客、官方 changelog / 文档 | 首选 | 是 |
| T1_5 | 平台数据与官方账号 | HF、GitHub 榜单、核心人物 X 账号 | 次选 | 是 |
| T2 | 媒体与社区 | TechCrunch、The Verge、HN、Reddit | 无 T1 / T1_5 时可用 | 是 |
| T3 | 二手聚合 | Ben's Bites、AIHOT | 不可，须回溯原文 | 否 |

- **报道面（N 源）**：同一事件有多少个独立来源。同一媒体多篇算 1，转载、编译同一稿算 1，T3 不算。必读每条都要标 `· N 源`，缺了 `verify_report.py` 会告警。
- **必读门槛**：重要度够线之外，还要报道面 ≥2，或至少有 1 个 T1 来源。只有一家非 T1 来源的独家、爆料，最多进「值得关注」，标题保留「据报」等归属。
- **代表稿**：标题链接放最一手的来源，优先级 T1 > T1_5 > T2；T3 永远不作代表链接。
- **不按名气打分**：重要度只看事情本身，来源级别只决定能不能进必读、用哪条链接，不给分数加减。

## 事件合并与跨期去重

同一批材料里，两两之间只有四种关系：

| 关系 | 判定 | 处理 |
|---|---|---|
| 同一事件 | 同一件事的不同报道（官宣 + 媒体转述） | 合并成一条，报道面累加，按优先级选代表稿 |
| 同一故事线 | 同一主题的不同进展（发布 → 调价 → 下架） | 主条只写最新、最重要的进展，其余进附录或一句带过 |
| 无关 | 主体或事情不同 | 分开处理 |
| 汇总稿 | newsletter、「本周 AI 大事」类合集 | 不作独立条目，只用来查漏，回溯其中各条原文 |

跨期去重：

- 动笔前先跑 `python scripts/ledger.py --reports ./ai-radar-reports --issues 7`，拿到近 7 期的必读台账。
- 台账里已有的事件，本期满足以下**任一条件**才能再进必读：① 当事方有新动作，例如新公告、新产品、新数据、新处置或诉讼进展；② 本期有 ≥4 个独立来源跟进。
- 达不到的进「🔁 续报」一行带过；没有新信息就不写。
- 「新动作」看事实，不看标题：媒体换个角度重写、评论文章、二手汇总都不算。

## 周报 / 月报的差异

周报、月报不是「日报变长」，而是**趋势提炼**。把当期全部条目按 8 类归并后：

- 开头换成「本期大事记」（3-5 句概括最重要的行业走向，而非逐条罗列）。
- 加一节「📈 趋势研判」：模型 / 工具 / 开源 / 产品商业四个维度，各 2-4 句讲清这一周/月的方向。
- 加一节「🔭 下期关注」：3 条值得盯的方向。
- 必读区改为「本期重大事件」（≥8 分全列），附录同样沉底。
- **先从日报汇编**：有日报存档时，先跑 `python scripts/ledger.py --reports ./ai-radar-reports --compile --days 7`（月报用 `--days 30 --top 30`）。它按头条、必读、关注、续报的出现位置加权，给出候选事件排序；再用本期抓取补漏。存档不足时照常抓取。
- **大事记和趋势只概括条目里的事实**：出现的每个公司名、人名、数字，都要能在本期条目中找到。某句话需要条目之外的事实才能成立，就删掉这句。

## 写作要点

- **so-what 是灵魂**：每条必读的 ⚡ 行决定读者要不要展开。写「这事改变了什么、你能利用什么」，不要写「X 公司发布了 Y」。
- **行动要具体到能本周执行**：「评估 X」太虚；「本周用 X 在现有产品的 Y 场景跑个 benchmark，对比成本」才有用。
- **诚实优先**：信息少就说少，不拔高重要度凑必读；抓取有失败就在尾注标注。
- **数字用阿拉伯数字**，公司/产品用规范名，便于读者检索。

### 硬规则（违反即返工）

- **链接只用本期材料里的**：每个链接都必须来自本期 `radar.json`，或本期 WebSearch / WebFetch 实际打开过、记入 `verified_urls.txt` 的页面。不凭记忆补链接，不拼 URL。`verify_report.py` 会拦截。
- **不放大语气和范围**：原文说「部分用户」不写「全面」，「测试中」不写「上线」，「计划 / 据报」不写成既成事实。
- **排他词要有出处**：「首个 / 唯一 / 最大 / 第一 / 登顶 / 史上」只有原文明确这么说才能用，并保留归属，例如「OpenAI 称其为首个…」。
- **How / Why / 分析类不写成「发布」**：原文是教程、复盘、观点或研究解读时，标题不能写成「X 发布 Y」。
- **版本号、参数量照抄原文**：`49B` 不改成「490 亿」，`GPT-6.1` 不改成「GPT 6.1」。金额可以换算成中文单位。`verify_report.py` 会对「N 亿参数」类写法告警。
- **答案先行**：速览句和 ⚡ 行第一个分句就是结论，不以「据报道 / 据悉 / 近日 / 日前」开头，不复述标题。
